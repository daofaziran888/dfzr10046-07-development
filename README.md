# 维链工坊 · 维度建模与缓慢变化维加工平台

面向维度注册、缓慢变化维拉链、一致性维度核对、事实表装配、代理键生成、维度退化、迟到事实回补、汇总层派生、指标口径绑定与维度快照发布的数仓维度建模加工平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/WorkbenchView.vue|tsx  全部模块共享工作台
│   ├── src/data/modules.ts              18个业务模块配置
│   ├── src/api/              统一请求封装
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/resource.py  通用查询/导出/登记/动作接口
│   ├── app/services/<key>.py    每个模块独立领域逻辑
│   ├── app/services/base.py     共享服务骨架
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8003/api/health`

### 前端

```bash
cd frontend
npm ci
npm run dev
```

前端默认监听 `http://127.0.0.1:5176/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8003`。

## 约定

- 全部模块共享`frontend/src/views/WorkbenchView.vue|tsx`和一套资源路由。
- 每个模块仍保留独立`backend/app/services/<模块>.py`；纯前端保留
  `frontend/src/domain/<模块>.ts`，用于承载真实业务差异并维持36题位容量。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 值班交接

跨班排期通过 `shift_handover` 模块的值班交接单衔接：

- 交接单从「已送交」开局，由接班负责人「签收」或「拒收」、由交班负责人「撤回」，
  拒收或撤回后可「改派」给下一位当班人并重新送交。
- 同一轮并发打进来的签收 / 撤回 / 拒收只产生一个有效处分，后到的申请登记为
  「无效申请」留痕，不改写状态（`ShiftHandoverService._lock` 串行化）。
- 签收结论写入交接单的「签收结论」并同步到关联重跑任务的「交接签收」；签收人凭
  这次交接取得该任务的排期权限，`reprocess_task` 的「排期重跑」会校验
  `schedule_grant`。
- 已启动（重跑中 / 已完成 / 失败）的工作留在原班次，只有待排期工作随签收移交。
- `GET /api/shift_handover/verify?record_id=Q1` 或 `?at=...` 可凭单核实交班时刻与负责人。
- 动作接口支持 `actor`（经手人）与 `target`（改派目标）：`{ "action": "签收", "actor": "乙" }`。
